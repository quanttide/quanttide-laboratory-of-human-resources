# 问卷模块升级规划

## 当前流程

```
投递邮件 → 读取邮箱 → 缓存问卷链接 → 发送邮件 → 归档到文件夹
```

**痛点：**
- 问卷链接需要手动从邮箱缓存
- 候选人信息需要从邮件主题解析
- 依赖 lark-cli 发送邮件
- 状态靠邮件文件夹管理
- 无法追踪候选人是否已读

## 升级目标

**问卷通知从系统内发出，状态在系统内流转。**

## 阶段一：数据入库

将问卷相关数据从邮件迁移到系统。

**需要做的事：**
- 问卷链接存储到系统，HR 可在后台管理
- 候选人信息存储到系统，不再从邮件解析
- 投递记录存储到系统，关联候选人和岗位

**升级后的流程：**
```
候选人投递 → 系统记录 → HR 在后台看到新投递
```

## 阶段二：通知系统化

问卷通知从系统内发出。

**需要做的事：**
- 候选人投递后，系统自动发送站内信通知
- 通知内容包含问卷链接
- 通知状态可追踪（已读/未读）
- HR 可在后台看到通知发送状态

**升级后的流程：**
```
候选人投递 → 系统记录 → 自动发送站内信 → 候选人在系统内看到通知
```

## 阶段三：流程自动化

问卷流程完全自动化。

**需要做的事：**
- 候选人投递后，自动创建问卷任务
- 问卷任务关联候选人和问卷链接
- 候选人提交问卷后，系统自动更新状态
- 超时未提交，系统自动标记

**升级后的流程：**
```
候选人投递 → 系统记录 → 自动发送通知 → 候选人填写 → 系统记录提交 → 状态自动更新
```

## 阶段四：移除邮件依赖

完全移除邮件相关的代码和依赖。

**需要做的事：**
- 移除 lark-cli 依赖
- 移除邮件模板渲染
- 移除邮件文件夹归档逻辑
- 移除邮件发送日志

**最终状态：**
```
候选人投递 → 系统记录 → 自动发送站内信 → 候选人在系统内填写 → 系统记录提交 → 状态自动更新
```

## 关键变化对比

| 环节 | 当前系统 | 升级后 |
|------|----------|--------|
| 问卷链接 | 从邮箱缓存 | 系统内管理 |
| 候选人信息 | 从邮件主题解析 | 系统内存储 |
| 发送通知 | lark-cli 发邮件 | 系统内站内信 |
| 状态管理 | 邮件文件夹 | 数据库状态字段 |
| 已读追踪 | 无法追踪 | 系统内追踪 |
| 超时处理 | 人工检查 | 系统自动标记 |
